# 17 — Reusing zainpreneur-app's Service Schema (attributes · variants · values)

`zainpreneur-app` already ships a complete **configuration-pricing engine**.
Agency OS should reuse it, not reinvent it.

## The engine (as implemented in `src/lib/types.ts`)

```
AttributeRecord   attribute (displayType: pills|color|radio|select|image|multi_checkbox,
                             variantCreation: instantly|dynamically|never, allowCustomValue)
AttributeValue    value (code, priceExtra, color, image, isCustom)
ServiceAttribute  attribute on a service + exclusions (forbidden combos)
Variant           pre-combined selection (price, cost, margin, deliveryDays,
                             generation: instantly|dynamically|manual)
ConfigurationRule extra fields (priceMode: flat|per_selection|per_unit)
Quote             basePrice + variantExtra + attributeExtras
                  + configurationCharges + additionalServices − discount
ServiceRequest    service + variant + attributes[] + pricing + RequestSnapshot
                  + branch scope + effort + tasks + checklist
LeadProposal/LLine the proposal already priced by this engine,
                  with estimatedCost (ours, never on the PDF) + snapshot
```

## The rule (when attributes are allowed)

> **If the client chooses it and it changes the price → attribute/value.
> If it's an event or money movement → a plain typed column. Never the reverse.**

| Procedure | Use engine? | Verdict |
|---|---|---|
| Proposal/quoting | client picks pages/language/WhatsApp → price computes | ✅ REQUIRED |
| Module add-on quoting (HR) | attendance method/payroll config → 3k quote + build_spec | ✅ REQUIRED |
| Client portal intake | existing ServiceRequestWizard + `displayType: pills` = no jargon | ✅ REQUIRED |
| Template catalogue | `list_price` stays floor; variants carry cost/margin pre-quote | ✅ at scale |
| Demo builder | seed source + pages + language as selections | ✅ helpful |
| Deployment pricing | provider as values with priceExtra | ⚠️ pricing only |
| Delivery | reuse ServiceRequest (branch, effort, snapshot) as-is | ✅ built & tested |
| Exclusions | impossible combos blocked before proposal goes out | ✅ valuable |
| **Ledgers** (payouts/expenses/payments/investments) | exact immutable rows only | ❌ FORBIDDEN |
| Assets, credentials, events, campaign targets | registers/ledgers | ❌ no |

## Why it's genuinely valuable

1. **Honest line-by-line price breakdown** — the Quote engine *is* the
   "client sees why 3,000" requirement; no manual line arithmetic
2. **Margin before quoting** — Variant `{price, cost, margin}` +
   `estimatedCost` hidden from the PDF: "this 3k nets 1.6k" known pre-send
3. **No-jargon UI free** — pills/color/image pickers; the barber taps
   "fingerprint scanner", never reads "biometric API"
4. **Snapshots solved** — `RequestSnapshot` freezes config+pricing at
   accept; our price-snapshot principle already implemented + tested
5. **Catalogue learns** — `generation: 'dynamically'`: a reused quote
   configuration crystallizes into a named variant you now sell
6. **Exclusions** prevent impossible promises at quote time

## Changes to this plan

- `templates.list_price` → floor + optional configurator
- `proposal_lines` → **generated by the Quote engine**, snapshotted on
  accept (same tables, better producer)
- `module_orders.build_spec` → rendered from configuration selections
- Client portal intake = existing wizard, not a new design
- Ledger tables (v1 + v2 of this plan) stay untouched

## Strategic conclusion

The smartest Agency OS is built **on** zainpreneur-app's
catalogue → quote → request engine (plus its existing
`agency-os/` pages), with this plan's ledgers, vault, payout guard, and
deployment matrix added around it.
